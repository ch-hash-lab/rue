WebRTC Signaling

Rue provides a built-in WebRTC signaling server that handles peer connection management, room-based grouping, and SDP/ICE candidate exchange over WebSocket.

Overview

The signaling server manages the handshake process required for WebRTC peer-to-peer connections. It handles:

  • Peer registration and lifecycle
  • Room-based grouping for multi-party sessions
  • SDP offer/answer forwarding
  • ICE candidate relay
  • Join/leave notifications

Basic Usage

Create a signaling server and attach it to a WebSocket endpoint:

go 
r := rue.Default()

signaler := rue.NewSignalingServer()

r.GET("/signal", func(c *rue.Context) {
    signaler.WebSocketHandler().Handle(c)
})

r.Run(":8080")

When a client connects, the server automatically assigns a unique peer ID and sends it back:

json 
{"type": "connected", "payload": {"peerId": "peer-abc123..."}}

Signal Types

The signaling protocol uses the following message types:

Type Direction Description
join Client → Server Join a room (broadcasts join notification to room peers)
leave Client → Server Leave current room (broadcasts leave notification)
offer Peer → Peer SDP offer forwarded to a specific peer
answer Peer → Peer SDP answer forwarded to a specific peer
candidate Peer → Peer ICE candidate forwarded to a specific peer

Rooms

Peers can join rooms for group communication. A peer belongs to at most one room at a time — joining a new room automatically leaves the previous one.

javascript 
// Client-side: join a room
ws.send(JSON.stringify({
    type: "join",
    room: "meeting-42"
}));

// Client-side: send an offer to a specific peer
ws.send(JSON.stringify({
    type: "offer",
    to: "peer-xyz789",
    payload: {
        type: "offer",
        sdp: localDescription.sdp
    }
}));

// Client-side: send ICE candidate
ws.send(JSON.stringify({
    type: "candidate",
    to: "peer-xyz789",
    payload: {
        candidate: candidate.candidate,
        sdpMid: candidate.sdpMid,
        sdpMLineIndex: candidate.sdpMLineIndex
    }
}));

Event Callbacks

Monitor signaling events with callbacks on the server:

go 
signaler := rue.NewSignalingServer()

signaler.OnPeerJoin = func(peer *rue.SignalingPeer) {
    log.Printf("Peer %s joined room %s", peer.ID, peer.Room)
}

signaler.OnPeerLeave = func(peer *rue.SignalingPeer) {
    log.Printf("Peer %s left", peer.ID)
}

signaler.OnMessage = func(msg *rue.SignalMessage) {
    log.Printf("[%s] %s → %s", msg.Type, msg.From, msg.To)
}

Server-Side API

The signaling server exposes methods for programmatic control:

Method Description
AddPeer(id, conn) Register a peer with a WebSocket connection
RemovePeer(id) Remove a peer and clean up room membership
JoinRoom(peerID, roomID) Move a peer into a room
LeaveRoom(peerID) Remove a peer from their current room
GetPeer(id) Look up a peer by ID
GetRoomPeers(roomID) List all peers in a room
SendTo(peerID, msg) Send a signal message to one peer
Broadcast(roomID, msg, excludeID) Broadcast to all room peers except one
PeerCount() Total connected peers
RoomCount() Total active rooms

Full Example

A video chat signaling server with room management:

go 
r := rue.Default()

signaler := rue.NewSignalingServer()

signaler.OnPeerJoin = func(peer *rue.SignalingPeer) {
    log.Printf("Peer %s joined room %s (peers: %d)",
        peer.ID, peer.Room, signaler.PeerCount())
}

signaler.OnPeerLeave = func(peer *rue.SignalingPeer) {
    log.Printf("Peer %s disconnected (rooms: %d)",
        peer.ID, signaler.RoomCount())
}

// Signaling endpoint
r.GET("/signal", func(c *rue.Context) {
    signaler.WebSocketHandler().Handle(c)
})

// Stats endpoint
r.GET("/stats", func(c *rue.Context) {
    c.JSON(200, rue.H{
        "peers": signaler.PeerCount(),
        "rooms": signaler.RoomCount(),
    })
})

r.Run(":8080")
Note

The signaling server only handles the connection setup. Actual media streams flow directly between peers via WebRTC. The server never sees audio/video data.
